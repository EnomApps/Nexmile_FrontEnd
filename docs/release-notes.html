Onboarding

First launch through to a signed-in customer.

ScreenWhat it does
SplashThree-second branded animation — orange dot expands, logo fades in, shine sweep, tagline, then four feature icons. Runs at 60 fps.
LanguageAll 23 official Indian languages. English is the default; English and Tamil lead the list. Searchable.
Sign inOne field accepting either an email address or a mobile number.
VerificationSix-digit code with a resend cooldown driven by the server.

Why there is no sign-up screen The API has no registration, password or password-reset for customers. An account is created automatically on the first successful code verification — so signing in and signing up are the same two screens, and there is no password for a customer to forget.

Location & address book

Delivery is limited to a radius the server sets, so a precise pin is not optional.

ScreenWhat it does
PermissionExplains why location is needed — delivery radius, pin accuracy, privacy — before the system prompt appears.
Map pinOpens on the GPS fix with the delivery circle drawn. The pin is dragged to adjust.
Address formReverse-geocoded prefill; label, landmark, city, PIN code and contact.
Address bookAdd, edit, delete, and set the default address.

Coordinates are mandatory The API requires latitude and longitude on every saved address, so the map step cannot be skipped — only the GPS part can, in which case the customer drags the pin themselves rather than being blocked.

Storefront

What is open, nearby, and worth ordering right now.

ScreenWhat it does
HomeNearby restaurants for the saved delivery address, with distance, prep time and minimum order.
Food RescueSurplus-food deals carousel showing the discount and portions remaining.
SearchServer-side search across nearby restaurants, debounced so typing does not flood the API.
RestaurantBanner, hours, menu by category, veg and non-veg marks, discount badges.

A closed shop says why “Not taking orders” when a restaurant is inside its hours but has paused, “Closed right now” when it is outside them. Only one of those is worth waiting for, so the customer is told which. Sold-out dishes are shown struck through rather than hidden — otherwise a customer hunting a favourite thinks the shop stopped selling it.

Cart & checkout

From add-to-cart through to a placed order.

ScreenWhat it does
CustomiseAdd-on groups with their required and optional rules enforced before the item can be added.
CartQuantity stepper, per-item notes, and the full bill broken down.
CheckoutDelivery or pickup, address picker, order note, cash on delivery.

Baskets survive the app closing Carts live on the server, one per restaurant, so an unfinished basket outlives closing the app or changing phones. A “you left something at —” bar surfaces it on the home screen.

One source of truth for checkout The checkout button is gated on the server’s own eligibility flag, which already accounts for the minimum order, sold-out items and opening hours. The app never second-guesses it — so what the customer sees always matches what the kitchen will accept.

Orders

After the order is placed, through to delivery and the invoice.

ScreenWhat it does
HistoryIn-progress orders lifted above completed ones.
Order detailItems, the full bill, a progress timeline, and the pickup code.
Live trackingRefreshes every eight seconds — the delivery partner’s name, a call button, and their live position on a map.

Tracking knows when to stop Polling ends the moment an order is delivered or cancelled, so a finished order does not sit in the background draining the battery.

Account

Profile, signed-in devices, and leaving.

ScreenWhat it does
ProfileName, email, mobile, verification badge and account status.
Edit profileChange the name, email address and mobile number.
DevicesEvery device holding a session, with its last-used time. Sign out one, or all of them.
Delete accountTwo-step confirmation before anything happens.

Why the app asks for a name Accounts are created named “Nexmile user”, so the profile screen prompts for a real one — that is the name the restaurant and the delivery partner read off the ticket.

Deleting is a soft delete Past orders and invoices are retained for GST records, which is a legal requirement, while the customer is signed out everywhere.

Testing

108 automated tests run on every change. They cover:

  • All 23 languages resolving their own copy, with no accidental English fallback
  • Placeholders surviving translation in every language
  • Layout on a 320×568 screen at 130% text scale, and right-to-left mirroring
  • Token refresh, including concurrent requests sharing a single refresh
  • Cart, checkout and order-status rules
  • Defensive decoding of the API’s mixed data types

Known limitations

All four are backend constraints rather than app work outstanding.

  • Cash on delivery is the only payment method The API documents online payment as not yet available. The checkout sheet is built to take more methods the moment the backend offers them.
  • The delivery radius is set by the server Currently 2 km for the nearby search. The app displays whatever the server returns rather than hard-coding a distance.
  • Live tracking depends on the rider app The map appears once a rider position is actually being reported.
  • Account language is limited to three The API accepts English, Tamil or Hindi as the saved preference. The app still offers all 23 on the phone; the other 20 simply are not sent to the server.

Installing

  1. Copy Nexmile-Customer-v1.0-arm64.apk to the phone.
  2. Open it. Android will ask permission to install from this source — allow it.
  3. Sign in with an email address or mobile number, and the code that arrives.
